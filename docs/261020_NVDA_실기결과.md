### 진행 방식과 한계

- 실제 NVDA에 키를 넣은 것은 사람이 아니라 Claude Code가 보낸 SendInput 키다(NVDA "다른 응용 프로그램의 키 처리" 기본값). NVDA가 읽은 문장은 NVDA 음성 출력 뷰어 창의 텍스트를 그대로 옮겼다(뷰어는 기호 처리 전 문자열이므로 "+"가 실제로 "플러스"로 소리 나는지는 기호 사전으로 확인).
- **귀로 듣는 항목(확인음, 음량, 겹침의 체감)과 손으로 누르는 항목(숙제 7)은 사람이 확인하지 않았다.** 확인음은 서버 신호 수락 여부로만 판정했다.
- 주입 방식 주의: 처음에 S 제스처의 모든 키를 SendInput 한 번에 묶어 보냈을 때, NVDA가 Ctrl·Shift를 계속 눌린 것으로 처리해 다음 NVDA+T가 `repeat` 신호로, 화살표가 "선택됨"으로 들어갔다. 키 사이에 40ms 간격을 두자 사라졌다. 사람 입력에서는 재현 근거가 없으므로 실패로 치지 않는다.
- 접속 코드는 사용자가 직접 입력했다. 코드는 이 문서·로그에 없다.

## 실패와 재현 절차 (원인 추정, 코드 수정 안 함)

**F1. 사본 런타임이 iframe에서 꺼짐 (최우선, 수집 차단)**
- 재현: 키트로 T09 과업 1(CJ 메인) 시작. 쿠키 대화상자의 "동의"를 NVDA Enter·Space, 마우스 클릭 어느 것으로도 닫을 수 없음. 과업 4(정상판)에서 SPORTS 칩 Enter·마우스 모두 무반응. Joyful Moments 캐러셀은 원본 배치로 펼쳐지고 "다음"에 응답 없음.
- 원인: 운영 사본 `public/s/<id>/runtime.js`가 `(() => { if (window.top !== window) return; …`로 시작한다. **30개 사본 중 25개**에 이 가드가 있다. 단일 창 기록기는 사본을 iframe에 넣으므로 쿠키 창 숨김(`.frame-cookie{display:none}`)·모션 고정·필터/캐러셀 대체 동작이 전부 실행되지 않는다. 출처는 lab `src/benchmark-*.ts`, `commercial-pair-*.ts`의 Playwright `addInitScript` 패턴(하위 프레임 제외용)이 런타임에 그대로 들어간 것으로 보인다. Linux `verify_single_window.cjs`가 이 사본 런타임을 거치지 않으면 통과할 수 있다.
- 영향: 25개 사본의 과업이 기록기 안에서 원래 설계대로 동작하지 않는다. 쿠키 창은 aria-modal이라 Tab으로 들어가면 NVDA 탐색이 대화상자 안에 갇힌다("다음 제목 없음" 반복).

**F2. 수행 중 기록 화면 머리글이 격리되지 않음 (no-go 5)**
- 재현: 과업 시작 → 사본 첫 요소에서 Shift+Tab, 또는 브라우즈 모드 Ctrl+Home. NVDA: "배너 랜드마크    A11y Task Recorder 홈  방문함  링크", "로컬 서버 연결됨", "NVDA 연결됨". 홈 링크에서 Enter.
- 결과: 본 과업은 사본이 `start_url`로 다시 로드(세션 active 유지, 진행 상태 사라짐). 연습은 사본 칸이 "연구 참여 접속" 화면으로 교체.

**F7. 노트북 배열만으로는 CapsLock 제스처가 동작하지 않음 (25)**

## 단축키 현실성 관찰 (숙제 7)

- **사람이 직접 누른 관찰은 없다.** 이번 실기에서 키는 모두 소프트웨어로 주입했다. 손 위치, 한 손·두 손 가능 여부, 노트북 자판 Insert/Fn 여부는 기록하지 못했다. 이 PC는 데스크톱이다.
- 기계적으로 확인한 사실: 데스크톱 배열 Insert+Ctrl+Shift+S/T/E는 모두 수락됐다. 노트북 배열은 CapsLock을 NVDA 키로 켜야 동작했고, 켜지 않으면 NVDA가 "캡스락 켬"이라 말하고 대문자 잠금이 켜졌다.
- 남은 관찰(사람, 노트북): 같은 세 조합을 데스크톱·노트북 배열에서 한 손·두 손으로 눌러 보고, 손가락 배치와 실패 횟수를 그대로 적는다.
