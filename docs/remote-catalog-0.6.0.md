# 원격 과업 배정 (0.6.0)

키트를 다시 만들지 않고, 사본 서버에 올린 배정표로 과업을 더하고 빼고 고친다. 코드는 `recorder/remote_catalog.py`, 테스트는 `tests/test_remote_catalog.py`다.

## 동작

- 기록기는 시작할 때와 그 뒤 1분마다 `<업로드 주소의 origin>/study/catalog/<키트 배정표 id>`를 받는다. 비밀번호는 업로드와 같은 키트 내장 코드(bearer)다. 코드가 없는 키트는 받지 않는다.
- 새 배정표는 **다음 과업을 준비할 때만** 적용된다. 준비 시점은 테스터 번호를 넣을 때, 과업 결과를 저장한 직후, 기록 화면을 다시 열 때다. 과업 수행 중이나 결과 입력 중에는 바뀌지 않는다.
- 지시문 화면에 이미 떠 있는 다음 과업은 그 과업을 마칠 때까지 옛 판으로 남는다. 테스터 번호를 넣기 전, 또는 앞 과업을 저장하기 전에 올려야 바로 반영된다.
- 서버에 파일이 없거나(404) 연결이 안 되면 키트에 들어 있던 배정표로 그대로 진행한다.
- 상태는 기록 화면의 `GET /api/uploads` 응답 `catalog`에서 본다: `revision`(쓰는 판), `pending_revision`(받았지만 아직 적용 전), `checked_at`, `applied_at`, `last_error`.

## 지켜지는 규칙

| 규칙 | 어기면 |
|---|---|
| 배정표 `id`가 키트 배정표와 같다 | 받지 않음(`last_error`에 invalid) |
| `revision`이 정수 1 이상이고 지금 쓰는 판보다 크다 | 적용하지 않음 |
| 모든 `start_url`이 키트 배정표에 있던 사이트(origin) 안에 있다 | 받지 않음 |
| 결과가 저장된 배정(`id`)은 같은 `task_id`를 유지한다 | 그 판 전체를 버림 |
| `upload_url`은 바꿀 수 없다 | 키트 값으로 덮어씀 |

- 저장된 결과는 지우거나 바꾸지 않는다. 배정에서 빠진 과업의 결과도 DB와 결과 패키지에 남는다.
- 준비만 되고 시작하지 않은 과업(draft)의 내용이 바뀌었으면 그 시도를 `aborted`(`abort_reason = catalog_update`)로 닫고 새 판으로 다시 준비한다.
- 시도마다 `study.catalog_revision`이 남아, 어느 판으로 수행했는지 분석에서 가를 수 있다.

## 연구진이 할 일

1. 키트를 만들 때 쓴 배정표를 복사해 고친다. `id`는 그대로 두고, `revision`을 1부터 하나씩 올린다. 과업 순서(`order`)는 테스터마다 1부터 빈틈없이 다시 매긴다.
2. 사본 서버의 배정표 폴더(`serve-hosted-benchmark.ts --catalog-dir`)에 `<id>.json`으로 저장한다. 서버는 요청마다 파일을 새로 읽으므로 다시 시작할 필요가 없다.
3. 1분 안에 각 PC의 `pending_revision`이 새 판이 되고, 다음 과업 준비 때 `revision`이 바뀐다.

배정표 파일에는 비밀값이 없지만 과업과 사본 주소가 들어 있으므로 공개 저장소에는 올리지 않는다.
