# 0.5.0: 참가자 피드백 반영 (10/28)

10/28 파일럿 참가자 피드백에서 나온 요구와 바꾼 내용입니다. 원칙은 하나입니다. 참가자에게는 과업 수행에 꼭 필요한 정보만 들려줍니다.

| 피드백 | 바꾼 것 | 위치 |
|---|---|---|
| 단축키를 자꾸 말해 줘서 중복이 많음 | 단축키는 연습 안내(`PRACTICE_GUIDE`)에서만 말한다. 지시문, 다시 듣기, 버튼 이름, 사이트 프레임 이름에서 끝내기 문장과 단축키를 모두 뺐다 | `static/study.js`, `recorder/signals.py`, `static/index.html` |
| 시나리오만 주고 TMI 삭제 | 지시문은 배정표의 시나리오 문장만 읽는다. 사이트 이름, 테스터 번호, 제한 시간, 경과 시간, 4과업 휴식 문구를 화면에서 뺐다 | `render()` |
| 쓸데없는 소리가 너무 많이 들림 | 진행 문구("준비하고 있습니다" 등)는 화면에만 보이고(`aria-hidden`) 읽지 않는다. 오류만 `role="alert"`로 읽는다. 머리글의 연결 상태 표시, 바로가기 링크, 바닥글은 참가자 화면에서 `inert`. 작업 중 버튼을 비활성화하지 않아 초점이 페이지로 떨어지며 읽히던 소리를 없앴다 | `message()`, `busy()`, `app.js showView` |
| 크롬 창으로 초점이 날아감 | 과업 중 사이트 프레임 앞뒤의 빈 초점 덫이 Tab/Shift+Tab을 사이트 안 첫/마지막 요소로 돌려보낸다. 기록 화면의 다른 곳에 초점이 가도 사이트로 돌려보낸다. 키트는 Chrome을 주소창 없는 앱 창(`--app`)으로 연다. NVDA+Ctrl+E로만 결과 화면으로 넘어간다 | `onFocusIn()`, `content.js`, `build_release_kit.py` |
| 화면이 바뀌면 시나리오를 알려 주기 | 과업 화면이 나오는 즉시 지시문에 초점을 두어 읽게 하고, 사이트는 뒤에서 준비한다. 과업 시작을 일찍 누르면 준비가 끝나는 대로 시작한다 | `prepare()`, `loadSite()`, `start()` |
| 과업 선택 없이, 추가 로드 없이 진행 | 결과를 저장하면 저장 확인 화면과 다음 과업 버튼 없이 바로 다음 지시문을 읽는다. 결과 수정 단계는 뺐다. 제한 시간으로 끝난 과업만 "다음 과업" 버튼에서 멈춘다 | `finish()` |
| 테스터 번호를 고르지 말고 입력 | 목록 대신 입력 칸. "1", "01", "t1", "T01"이 모두 T01이다. 없는 번호는 오류로 읽는다 | `matchTester()` |
| 연습을 제대로, 언제든 다시 | 처음 번호를 넣으면 연습이 저절로 열린다. 과업을 시작하기 전이면 "연습 다시 하기"로 언제든 연다. 연습이 끝나면 H와 E를 실제로 썼는지 알려 준다 | `startPractice()`, `practiceSubmit()` |
| 과업을 다시 시작할 수 있게 | 결과 화면의 "과업 처음부터 다시 하기"(0.4.4 기능 유지). 사이트 아래 마우스용 버튼은 NVDA에서 숨겼다 | `restartTask()` |
| 마쳤습니다/마치지 못했습니다 표현 | "과업에 성공했나요?" 성공/실패. 저장 값(`completed`/`blocked`)은 그대로 | `index.html` |

## 확인한 것

- Python 110개(2개 건너뜀), node 34개 통과.
- 헤드리스 Chromium 흐름 점검(확장 응답과 NVDA 연결은 합성): 번호 입력, 없는 번호 오류, 연습 자동 시작, Tab/Shift+Tab 각 9번에도 초점이 사이트 안, 과업으로 돌아가기 뒤 페이지 상태 유지, 연습 결과의 단축키 사용 안내, 지시문이 시나리오 문장과 같음, 저장 뒤 바로 다음 지시문, 과업 2 앞에서 연습 다시 하기, 새로 고침 뒤 연습이 다시 열리지 않음.

## 실제 NVDA에서 볼 것

1. 과업 화면이 나올 때 지시문만 읽히는지(앞뒤에 다른 문장이 붙지 않는지).
2. 과업 중 Tab을 계속 눌러도 Chrome 도구 모음이나 기록 화면으로 나가지 않는지. 브라우즈 모드에서 사이트 끝을 지나 아래 화살표를 눌렀을 때 기록 화면 문장이 읽히지 않는지.
3. 저장 뒤 다음 지시문이 바로 읽히는지, 그 사이에 "A11y Task Recorder" 같은 소리가 끼지 않는지.
4. 연습 안내 문단의 길이가 적당한지. 길면 문장 단위로 나눈다.
5. 앱 창(`--app`)에서 확장과 NVDA 애드온이 그대로 동작하는지.
