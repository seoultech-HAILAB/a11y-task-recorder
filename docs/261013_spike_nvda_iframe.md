# 10/13 스파이크 절차: 한 창 기록기의 NVDA 미지수 4개 확인

작성 2026-10-12. 대상: 연구원(김유신)이 SNC 수집용 노트북(또는 자기 Windows PC)에서 혼자 따라 하는 절차. 원격 조작은 하지 않는다. 결과는 아래 기록표에 적어 `docs/261013_실기_점검표.md`의 해당 항목에 옮긴다.

미지수(계획서 `261012_single_window_plan.md` §3.6):

1. `iframe.focus()`를 하면 NVDA 브라우즈 모드 커서가 프레임 안으로 들어가고, Tab·화살표·H·B가 프레임 안에서 움직이는가.
2. 프레임 안 요소가 애드온에 `scope=web_content`, `frame=task`로 잡히는가(기록 확인).
3. `SameSite=None; Secure; Partitioned` 쿠키로 프레임 안 로그인이 유지되는가. **사본 서버를 다시 시작한 뒤에만 확인 가능**(§C).
4. 초점 이동으로 지시문·결과 머리글이 끝까지 읽히는가, 아니면 `ui.message`가 필요한가.

소요 시간 약 40분. 소리는 노트북 스피커로 듣는다(수집 환경과 같게).

## 준비물

- 키트 0.4.0 ZIP을 `C:\a11y-pilot\kit\`에 풀어 둔다(배포용이 아니라 스파이크용. 배포는 10/15 go 뒤).
- 이 폴더(`docs/spike-20261013/`)를 노트북에 복사한다(`top.html`, `frame.html`, `spike.css`, `spike.js`, `frame.js`, `실행.bat`).
- NVDA 2026.1 이상. 키보드 배열은 **노트북**으로도 한 번, 데스크톱으로도 한 번 확인한다(NVDA 메뉴 > 설정 > 키보드 > 키보드 배열).

## A. 정적 스파이크 페이지 (미지수 1, 4의 절반) 약 15분

사본 서버·확장·기록 서버 없이 두 출처(127.0.0.1:8788 상위, localhost:8789 프레임)로 한 창 구조만 흉내 낸다.

1. `실행.bat`을 실행한다. 서버 창 두 개와 Chrome이 열린다(키트 Chrome, 별도 프로필). 키트 경로가 다르면 bat 안의 `KIT` 값을 고친다.
2. NVDA를 켠 채 Chrome 창이 앞에 오면 **NVDA+T**로 창 제목을 듣는다. 기록: "스파이크: 한 창 기록기" 인지.
3. **지시문 읽기(미지수 4-a).** Tab으로 `1. 지시문에 초점` 버튼까지 가서 Enter. NVDA가 과업 문장을 끝까지 읽는지, 역할("문장"/"텍스트")만 읽는지, 아무 말도 없는지 기록. 화살표 위·아래로 지시문을 되읽을 수 있는지도 기록.
4. **시작(미지수 1).** `2. 시작` 버튼에 Enter. 기록:
   - NVDA가 무엇을 읽는가(예: "프레임", "문서", 프레임 첫 줄, 아무것도 안 읽음).
   - 아래쪽 화살표 두 번: 읽히는 내용이 프레임 안 "오늘의 요리: 두부조림"으로 이어지는가.
   - H 키: 프레임 안 머리글(조리법, 보관 팁)로만 가는가, 상위 문서의 "스파이크" 제목으로 올라가는가(올라가면 aria-hidden이 안 먹는 것).
   - B 키: `재료 보기`로 가는가. Enter 뒤 "재료는 두부, 대파, 간장입니다"가 들리는가(aria-live).
   - Tab을 프레임 끝(`프레임의 마지막 버튼`)에서 더 누르면 어디로 가는가(주소창 등 브라우저 UI면 정상, 상위 문서 버튼이면 비정상).
   - 입력란에 Tab으로 들어갈 때 포커스 모드 전환음이 나는가.
   - `새 창 링크(막혀야 함)`에 Enter: 새 탭·창이 열리지 않아야 한다.
   - NVDA+T: 제목이 "오늘의 요리: 두부조림 (프레임 제목 미러링)"인가.
   - "프레임", "프레임 끝"이 읽히는 횟수와 위치(NVDA 문서 서식 "프레임 알림" 기본 켬).
5. **종료(미지수 4-b).** 상위 문서로 가야 `3. 종료` 버튼을 누를 수 있는데 수행 단계에서는 숨겨져 있다. 대신 **Ctrl+Alt+E**(스파이크 전용, 상위 문서에 초점이 있을 때만 동작)를 쓰거나 마우스로 `3. 종료`를 누른다. 기록:
   - "과업이 끝났습니다. 결과를 입력해 주세요"가 끝까지 읽히는가.
   - Tab: 라디오 "마쳤습니다"로 가는가. Space로 고르고 Tab으로 답 입력란, Enter로 저장까지.
   - 결과 단계에서 Tab·화살표·B로 프레임 안 요소에 갈 수 있는가(갈 수 있으면 inert가 안 먹는 것).
   - 저장 뒤 "저장했습니다. 답: …"이 읽히는가.
6. 노트북 배열로 바꾼 뒤 2~5를 한 번 더 한다(차이만 기록).

## B. 키트 0.4.0 연습 모드 (미지수 2, 4의 나머지, 제스처) 약 15분

사본 서버가 필요 없는 연습 모드로 제스처와 `ui.message`를 확인한다.

1. 키트 0.4.0의 `평가시작.bat`을 실행한다(NVDA 재시작, 애드온 0.4.0 설치, 서버, Chrome). 대시보드가 열린다.
2. 진행자 패널의 `연습 시작`을 누른다. 초점이 지시문으로 간다. 기록: 지시문이 읽히는가.
3. **NVDA+Ctrl+Shift+T**(다시 듣기): 높은 확인음 뒤 NVDA가 "연습입니다. 연습 화면에서 …"를 **자기 목소리로** 읽는가(이것이 `ui.message`). 중간에 키를 누르면 끊기는지도 확인.
4. **NVDA+Ctrl+Shift+S**(시작): 확인음 뒤 1초 안에 프레임으로 초점이 가고 "오늘의 요리" 화면이 읽히는가. A-4의 항목(화살표, H, B, Tab 순환, NVDA+T)을 다시 한 번.
5. **NVDA+Ctrl+Shift+E**(종료): 낮은 확인음(660Hz) 뒤 결과 머리글이 읽히는가. 라디오·답·저장을 키보드로 끝까지.
6. 저장 뒤 `연습 끝내기`.
7. 노트북 배열(NVDA 키 = CapsLock)로 3~5를 반복. 기록: CapsLock+Ctrl+Shift+S/T/E가 한 손 또는 두 손으로 눌리는지, 눌리지 않는 조합이 있는지, 노트북 자판에 Insert가 있는지(없으면 데스크톱 배열은 쓸 수 없음).
8. 제스처 충돌 확인: NVDA 메뉴 > 설정 > 입력 제스처에서 "A11y Task Recorder" 범주를 열어 S/T/E가 다른 명령과 겹친다는 표시가 없는지 본다.
9. 미지수 2: 연습은 기록하지 않으므로 **배정 과업 1건을 로컬 리허설**로 돈다. 사본 서버 재시작 전에는 사이트 준비가 접속 코드 단계에서 멈추므로(쿠키 문제), 이 항목은 §C 뒤에 한다.

## C. 사본 서버 재시작 뒤 (미지수 2, 3) 약 10분

연구원이 `261012_구현_보고.md` §재시작 명령대로 4319를 다시 시작한 뒤:

1. 키트 0.4.0 대시보드에서 T01 선택, `사이트 준비`. 프레임 안에 "연구 참여 접속" 폼이 나오면 접속 코드를 넣고 `접속`.
2. 기록: `기록 시작` 버튼이 나타나는가(쿠키 유지). 새로고침해도 다시 묻지 않는가.
3. `지시문 읽기` 뒤 NVDA+Ctrl+Shift+S로 시작. 사본에서 Tab 5번, H 2번, Enter 1번. NVDA+Ctrl+Shift+E로 종료. 라디오·답 입력·저장.
4. `상세 기록`에서 NVDA 이벤트의 `element.scope`가 `web_content`, `element.frame`이 `task`인지, `frame=recorder`가 0건인지 본다(이벤트 CSV 또는 JSON 내보내기).
5. `다음 과업`을 눌러 두 번째 과업이 접속 코드 없이 준비되는지 본다.

## 판정 기준 (10/13 저녁)

- **진행(go 후보)**: A-4-2, A-4-3(안 올라감), A-4-5(브라우저 UI), A-5(머리글 읽힘), B-3, B-4, B-5가 모두 정상. A-3이 "안 읽힘"이면 `A11Y_RECORDER_ANNOUNCE=nvda`로 바꿔 `ui.message` 방식으로 간다(코드 변경 없음, 환경 변수 또는 bat 한 줄).
- **보류**: A-4-2 또는 A-4-3이 실패(가상 버퍼가 프레임을 한 문서로 다루지 않음, 또는 aria-hidden 무시). 이때는 결과 단계에서 iframe을 `hidden`으로 바꾸는 대안(계획서 §2.4)을 적용해도 수행 단계의 머리 영역 문제는 남으므로, 1차는 0.3.4로 간다.
- 미지수 3(C)은 사본 서버 재시작 뒤 10/15 점검으로 넘겨도 된다. Linux에서는 같은 쿠키 속성으로 Chromium 프레임 안 로그인 유지가 확인됐다(`scripts/verify_single_window.cjs`).
