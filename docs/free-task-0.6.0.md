# 자유 과업 (0.6.0)

배정 과업을 모두 마친 테스터가 원하면 직접 고른 사이트와 할 일로 과업을 하나 더 한다. 선택 사항이고, 기록은 배정 과업과 분리해 메모리(습관) 구축에만 쓴다. FE 비교와 SNC 지표에는 넣지 않는다.

## 흐름

1. 완료 화면 아래 "자유 과업 (선택)"에 사이트 주소와 하려는 일을 적고 **자유 과업 시작**을 누른다. 주소는 `www.example.com`처럼 적어도 되고, 앞에 `https://`가 붙는다.
2. 사이트가 **새 브라우저 창**(주소창 없는 popup 창, 최대화)으로 열리고 초점이 페이지에 간다(0.6.1). 실제 사이트는 대부분 기록 화면 안의 프레임에 넣을 수 없어서(X-Frame-Options, CSP `frame-ancestors`) 프레임 대신 창을 쓴다.
3. 끝낼 때는 배정 과업처럼 NVDA+Ctrl+E를 누른다. 10분이 지나면 저절로 끝난다. 사이트 창이 닫히고 기록 화면의 결과 칸(했습니다/못 했습니다, 하고 싶은 말)으로 초점이 온다.
4. **저장**하면 결과가 저장되고, 서버로 자동 업로드된다(코드 내장 키트). 자유 과업은 몇 번이든 더 할 수 있다.

## 기록 범위

- 확장은 자유 과업 창의 탭(그 창에서 링크로 열린 새 탭 포함)의 모든 프레임만 기록한다. 기록 화면과 다른 창은 기록하지 않는다.
- NVDA 애드온은 기록 화면(`http://127.0.0.1:8765`)이 아닌 문서 안의 입력을 `frame = "task"`로 남긴다(탐색 모드 버퍼의 문서 식별자, 즉 페이지 URL로 가린다).
- 세션 `study`에 `kind = "free"`, `free_index`(테스터별 1부터), `ui_mode = "free_tab"`이 붙는다. `study_attempts` 행이 없어 배정 진행에는 영향이 없다.
- 시작하지 않은 자유 과업은 새로 고른 과업으로 바뀌고 `aborted`(`free_task_replaced`)로 남는다. 한 번에 하나만 진행한다.

## 0.6.1 (Windows 실기 11/02, `261102_NVDA_실기결과_0.6.0_자유과업.md`)

- NVDA+Ctrl+E가 2회 모두 무시됐다. 시작 뒤 세션을 다시 읽지 않아 기록 화면이 자유 과업을 시작 전으로 알고 있었다. 시작 직후 다시 읽는다. 10분 제한도 같은 이유로 동작하지 않았을 것이다.
- 빈 창을 연 뒤 주소를 넣어 초점이 주소창에 남았다(페이지까지 F6 3번). popup 창을 사이트 주소로 바로 연다. 첫 페이지 로드는 창을 만들기 전에 상태를 저장하고 `tabs.onCreated`로 새 탭을 잡아 기록한다.
- 자유 과업 입력 156개 중 1개만 `frame = "task"`였다. NVDA가 Chrome 문서의 값(URL)을 숨기기 때문이다. 탐색 모드 버퍼의 `documentConstantIdentifier`(Chromium에서는 URL)를 먼저 읽는다.
- 그대로 둔 것: 네이버·구글은 열리자마자 검색 칸에 초점을 줘 포커스 모드가 되고, H·K가 글자로 들어간다. 사이트 자체의 동작이고 참가자가 평소 겪는 상황이라 바꾸지 않는다.

## 알려진 한계

- 0.6.1의 popup 창에서 첫 낭독과 초점 위치, `frame = "task"` 비율은 Windows에서 다시 확인해야 한다.
- 자유 과업 중에는 과업으로 돌아가기, 과업 다시 시작, 사이트 안 뒤로 가기 고정이 없다. 브라우저의 뒤로 가기와 새로 고침이 그대로 동작한다.
- 테스터가 로그인이나 결제를 하면 그 화면도 기록된다. 안내문에서 하지 말라고 하지만 막지는 않는다.
- 기록 화면을 다시 열면 진행 중인 자유 과업은 이어서 감시하지만, 결과 입력 중이던 화면은 되살리지 않는다.
