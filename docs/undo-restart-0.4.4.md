# 테스터 번호 바꾸기, 과업 다시 시작, 과업으로 돌아가기 (0.4.4 설계)

작성 2026-10-28. 기준 코드는 0.4.3(HEAD 3b84f2e). 요청: 테스터를 잘못 고르거나 과업을 잘못 시작해도 쉽게 되돌릴 수 있게 한다. **Windows/NVDA 실기 미확인**이다.

## 원칙

- 저장된 기록은 지우지 않는다. 취소한 시도도 그대로 남기고, 분석에서 뺄 수 있게 표시만 한다.
- 되돌리기는 모두 화면 안 버튼과 화면 안 확인 단계로 한다(`window.confirm`을 쓰지 않음). 확인 단계가 열리면 초점은 안전한 쪽(계속하기, 취소)에 둔다. Escape는 확인 단계를 닫는다.
- 상태 안내는 기존 상태 영역(`#study-message`, 수행 중에는 사이트 아래 `#study-site-status`)으로 읽힌다.
- NVDA 단축키는 늘리지 않는다. 0.4.2 단축키(끝내기 NVDA+Ctrl+E, 다시 듣기 NVDA+Ctrl+H)에 다시 시작을 더하면 한 번 누르는 것으로 기록이 취소되는 위험한 조합이 생기고, 알맞은 글자(R)는 NVDA 자체의 "저장된 설정으로 되돌리기"(NVDA+Ctrl+R)와 겹친다. 애드온을 다시 설치해야 하는 것도 부담이다. 키보드만으로 가는 길은 "NVDA+Ctrl+E로 끝낸 뒤 결과 화면에서 처음부터 다시 하기"로 충분하다.

## 1. 테스터 번호 바꾸기

- 테스터가 정해지면 위쪽에 **테스터 번호 바꾸기 (지금 T03)** 버튼이 보인다. 준비, 저장됨, 완료 단계에서만 보이고, 과업 수행 중과 결과 입력 중에는 숨긴다(수행 중이면 먼저 끝내거나 다시 시작한다). Tab 순서는 과업 시작, 연습 시작 다음이다.
- 그 번호로 저장된 결과가 없으면 확인 없이 번호 칸이 다시 나오고 초점이 번호 칸으로 간다. 번호 칸 옆 **바꾸지 않기**를 누르면 원래 번호로 돌아간다.
- 저장된 결과가 있으면 그 자리에 확인 단계가 열린다. "T03로 저장된 결과 2개는 지워지지 않고 그대로 남습니다. 다른 테스터 번호로 바꿀까요?" **번호 바꾸기**, **취소**. 초점은 **취소**.
- 다른 번호로 배정 확인을 하면, 바꾸기 전 번호에 시작하지 않은 준비 과업(draft)이 있을 때 그 과업을 `aborted`(결과 `cancelled`, 사유 `tester_change`)로 닫는다. 그래야 NVDA+Ctrl+H가 다른 테스터의 지시문을 읽는 일이 없다. 그 번호를 나중에 다시 고르면 같은 과업의 새 시도가 만들어진다.
- 연구자용 `?change-tester=1`, `?tester=T03`은 그대로 둔다.

## 2. 과업 다시 시작

- 수행 중: 사이트 아래 **과업 다시 시작** 버튼(과업 끝내기와 같이 Tab 순서 밖, 마우스와 브라우즈 모드로 닿음). 누르면 확인 단계 "과업을 처음부터 다시 할까요? 지금까지 한 내용은 분석에서 빠지고, 지시문부터 다시 시작합니다." **다시 시작**, **계속하기**. 초점은 **계속하기**.
- 결과 입력 중: 저장 버튼 아래 "잘못 끝냈을 때" 묶음에 **과업으로 돌아가기**, **처음부터 다시 하기**. 둘 다 Tab으로 닿는다. 처음부터 다시 하기는 같은 확인 단계를 연다(초점은 **취소**).
- 다시 시작하면 지금 시도를 닫고, 같은 과업의 새 시도를 준비 단계로 만든다. 사이트를 과업 시작 주소로 다시 열고, 초점은 지시문으로 간다. 지시문을 듣고 과업 시작을 누르면 새 기록이 시작된다.
- 연습에서도 같은 버튼이 같은 일을 한다(기록은 없음).

## 3. 과업으로 돌아가기 (끝내기를 잘못 눌렀을 때)

- 결과 입력 중 **과업으로 돌아가기**는 기존 서버 기능 `resume-task`(answering에서 active로)를 쓴다. 결과 입력 동안에는 NVDA·브라우저 이벤트를 받지 않았으므로(종료 5초 안의 늦은 이벤트만 `received_after_stop`) 기록이 섞이지 않는다. 사이트는 끝낼 때의 화면 그대로이고 초점은 사이트 프레임으로 돌아간다.
- 결과 입력에 머문 시간은 순수 과업 시간에서 뺀다(`task_resume`의 `gap_seconds`를 일시정지 시간처럼 합산). 제한 시간 타이머도 같은 값을 쓴다(세션의 `paused_seconds`).
- 제한 시간으로 끝난 과업은 돌아가거나 다시 시작할 수 없다(서버도 거부, 시간을 더 얻는 길이 되지 않게). 결과를 저장한 뒤에는 기존 **결과 수정**만 된다.
- 결과 입력 중에 기록 화면을 새로 고치면 사이트는 과업 시작 주소로 다시 열린다. 이때 돌아가기를 누르면 기록은 이어지지만 사이트 위치는 처음 화면이다.

## 데이터 모델

- 세션 상태 `aborted`를 새로 둔다. `completed`, `abandoned`(마치지 못함, 시간 종료)와 섞이지 않게 하려는 것이다.
  - `study_outcome`: `restarted`(다시 시작) 또는 `cancelled`(시작 전 번호 변경).
  - 새 열 `aborted_at`, `abort_reason`(`restart`, `tester_change`).
  - `ended_at`은 닫은 시각. 시작했던 시도는 `task_ended_at`, `net_task_seconds`도 채운다. `end_reason`은 이미 끝낸 뒤(결과 입력 중)라면 그 값을 두고, 수행 중에 다시 시작했다면 `restart`.
  - 대시보드 이벤트 `task_abort` `{reason, from_status, trigger, by, previous_end_reason, net_task_seconds, to_tester}`.
- 새 시도는 기존 재시도 구조를 쓴다. `study_attempts.attempt`가 1 늘고 `retry_of`가 취소된 세션을 가리키며, 세션의 `round`도 1 늘고 `group_id`는 같다. 진행도 계산은 과업마다 마지막 시도만 보므로 취소된 시도는 진행에 들어가지 않는다.
- `GET /api/sessions/<id>`에 `study_attempt` `{attempt, retry_of, next_attempt, analysis}`와 `paused_seconds`를 더한다. `analysis`는 `include` 또는 `exclude`(0.5.7부터 저장한 뒤 다시 한 과업의 앞 시도는 `superseded`, 새 시도에 `redo_reason`).
- API: `POST /api/sessions/<id>/abort` `{reason: restart|tester_change, trigger, by, to_tester}`. 다시 시작은 수행 중·결과 입력 중인 현재 과업에만, 번호 변경은 시작 전(draft) 과업에만 허락한다.

## 연구자 쪽

- 결과 패키지: 시작했던 취소 시도는 `sessions/aborted/` 아래에 따로 넣는다(JSON, CSV, interactions CSV). 모든 시도를 한 줄씩 적은 `attempts.csv`(테스터, 순서, 시도 번호, 이전 시도, 상태, 결과, `analysis`=include/exclude, 사유, 시각, 순수 시간)를 넣는다. `패키지정보.txt`에 취소된 시도 건수를 적는다.
- 세션 JSON의 `data_quality`에 `attempt_valid` 점검을 더한다. 취소된 시도는 실패로 표시되고 "분석에서 제외" 경고가 붙는다.
- 기록 관리 화면: 상태 이름 `aborted`는 "취소된 시도(분석 제외)", `answering`은 "결과 입력". 회차 탭에도 "취소"가 붙는다.
- 자동 업로드: 사본 서버의 업로드 받기가 `completed`, `abandoned`만 받으므로 취소된 시도는 올리지 않는다. 결과 패키지와 DB 백업에는 남는다.

## Windows/NVDA에서 확인할 것

- 테스터 번호 바꾸기 버튼과 확인 단계가 "…그룹, 취소 버튼"처럼 읽히는지, 번호 칸으로 초점이 가는지.
- 수행 중 사이트 아래 "과업 다시 시작"이 브라우즈 모드 아래 화살표로 읽히고 Enter로 확인 단계가 열리는지, Tab으로는 닿지 않는지.
- NVDA+Ctrl+E로 끝낸 뒤 결과 화면에서 Tab으로 "잘못 끝냈을 때 그룹, 과업으로 돌아가기 버튼"에 닿는지, 돌아간 뒤 사이트의 같은 자리에서 이어서 읽히는지.
- 다시 시작 뒤 지시문이 다시 읽히고, 과업 시작이 정상으로 기록되는지.
