# 수집 데이터 → 결과물 계획 (한 장 요약)

SNC 랩 평가에서 이 시스템으로 무엇을 받고, 그것으로 무엇을 만드는지의
요약입니다. 스키마 상세는 [로그기록계획.md](로그기록계획.md) 참고.

## 1. 받는 데이터

평가 1회(세션·회차)마다 **결과 패키지 ZIP 하나** — 세션별 JSON·CSV + 복구용 전체 기록 백업.

파일은 세 층으로 제공됩니다. 분석은 보통 ②로 시작합니다.

| 층 | 파일 | 용도 |
| --- | --- | --- |
| ① 원본 | `*.json`의 `events`, `*.csv` | 재현·검증용 원자료(발화 취소·DOM 변화 포함) |
| ② 행동 | `*.json`의 `interactions`, `*_interactions.csv` | 한 줄 = 한 행동(키→요소→발화→청취시간→URL). 사람이 읽고 pandas·Excel로 바로 집계 |
| ③ 지표 | `*.json`의 `summary` | 세션 단위 집계(시간·키 수·발화·중단 등) |

②는 ①을 접은 파생 뷰이며 `event_ids`로 원본을 되짚을 수 있어 정보 손실이
없습니다(실측: 705 이벤트 → 218 행동).

| 데이터 | 내용 |
| --- | --- |
| 상호작용 로그 | 키 입력 → 도착 요소(이름·역할·고유 ID) → NVDA 안내 전문 + 몇 초 듣고 넘겼는지(중단 여부) |
| 과업 구조 | step 정의, step별 시작·종료 시각, **수행 결과(성공/힌트 후 성공/막힘)와 사유** |
| 불편 신호 | 참여자 마커(시점·당시 요소·강도 1~5), 회고에서 등록한 문제 라벨(심각도·구간·기대 발화) |
| 맥락 | 페이지 이동 경로, 화면 변화 시각, 힌트 내용·시점, 종합 의견 |
| 환경 | NVDA 버전·합성기·발화 속도, 브라우저·확장 버전 (시간 지표 정규화용) |

## 2. 만드는 결과물

### ① 과업 수행 지표 (step·세션 단위 정량)
성공률(3분류), 소요 시간, 키 입력 수, Tab/탐색 단축키 전략 분포,
백트래킹·재방문 횟수, 발화 청취율(중단 비율·평균 청취 시간).
→ 사이트 간·참여자 간·**회차 간(학습 효과)** 비교, 에이전트 대비 시간·키 배율.

### ② 불편 지점 분석 (RQ3)
마커 시점 직전 행동 윈도우에서 패턴 추출(반복 Tab, 무발화, 되돌아가기)
→ 행동 패턴과 불편(강도 포함)의 연관. 문제 라벨을 KWCAG 위반 항목과 매핑해
전문가 감사(A11y-Agents 전문가 에이전트) 결과와 대조.

### ③ 발화 층위 이슈 증거 (G_User)
"화면은 변했는데(first_change_ts) 발화가 없었다/끊겼다" 구간 자동 검출
→ 실사용자 쪽 근거 데이터로 4.1.3 계열 이슈 목록 구성.

### ④ 에이전트 모사 충실도 기준선
같은 시나리오의 실사용자 로그 vs 사용자 에이전트 행동을
`URL+요소 이름·역할` 키로 정렬해 경로·전략 분포·막힘 위치 비교.

### ⑤ 에피소드 메모리 데이터셋 (C3)
각 상호작용을 observation(발화·포커스) / action(키) /
thoughts(마커·문제 라벨) / result(step 결과)의 4필드로 변환
→ 사용자 에이전트의 에피소드 메모리 재료.

### ⑥ 보고 산출물
참여자별 세션 리포트(타임라인 검토 화면·A11y-Agents 기록 탭),
사이트별 불편 종합표(전문가 감사 대조), 논문 데이터·ethics 기술
(로컬 우선·문자 비수집·query 제외 그대로 인용 가능).

## 3. 흐름

```text
SNC 평가(키트) → 결과 패키지 ZIP → A11y-Agents 기록 탭(검토)
                                  → 분석 스크립트(지표 ①~⑤) → 논문 표·그림
```
