# 로그 기록 계획 (2026-08 연구 gap 분석 반영)

연구 계획 문서의 데이터 요구(§6.5 gap 분석)와 **실제 수집 스키마**를 대조한
정본입니다. README의 "어떤 데이터가 기록되나요?"는 참여자 안내용 요약이므로,
분석 설계 시에는 이 문서를 기준으로 삼습니다.

## 1. 현재 수집 스키마 (이벤트 타입별 상세)

모든 이벤트 공통: `id`(전역 순번), `timestamp`(ISO, ms), `source`(nvda ·
browser · dashboard), `step_id`(활성 step 자동 연결), `url`, `page_title`.

| 타입 | 출처 | 주요 필드 |
| --- | --- | --- |
| `input` | NVDA | 키·제스처(`display_name`/`gesture`/`identifiers`), 당시 요소(`element.name`·`role`·`states`·**`ia2_unique_id`·`unique_id`**) |
| `focus` | NVDA | 포커스 도착 요소(이름·역할·상태·**고유 식별자**) |
| `speech_episode` | NVDA | 발화 **원문 전문**(`raw_text`·`fragments`), 전처리본(`normalized_text`), `speech_end_ts`, `interrupted`, 조각 수 |
| `speech_cancel` | NVDA | 발화 취소 시각과 당시 요소 |
| `marker` | NVDA/대시보드 | 불편 표시 시각, **당시 포커스 요소 맥락**, 제스처 |
| `hint` | 대시보드 | 힌트 내용 + **제공 시각** + 당시 step |
| `step_start` / `step_end` | 대시보드 | step 제목·position, 종료 사유(`reason: next_step_started` 등) — **타임라인에 명시 이벤트로 기록됨** |
| `navigation` / `history` | 확장 | URL(쿼리 제거), 이동 방향 추론, transition |
| `page_ready` | 확장 | 로드 완료 시각, 제목 |
| `dom_mutation` | 확장 | **배치별 타임스탬프**(마지막 변화 +450ms 디바운스), 추가/삭제/속성/텍스트 변화 수, 속성명·XPath 목록(내용 비수집) |

세션 환경(자동 병합): NVDA 버전, 합성기, **발화 속도(`speech_rate`)**,
브라우저·확장 버전. 세션 메타: 시나리오·참여자 코드·step 정의·힌트·문제
라벨(심각도 4단계·태그·이벤트/step 구간)·종합 의견.

## 2. 연구 피드백(P1/P2) 대조 결과

| 제안 | 실제 상태 | 판정 |
| --- | --- | --- |
| P1-1 step별 결과 코드(Complete/Assisted/Blocked+사유) | 없음 — steps에는 진행 상태만 존재. (step 경계 이벤트는 이미 기록됨) | **구현 (아래 §3.1)** |
| P1-2 불편 강도(1~5)+사유 | 부분 — 시점·포커스 맥락은 있음. 회고의 문제 라벨에 심각도·설명 존재(회고 평가). 즉시 자기보고 강도는 없음 | **구현 (§3.2)** |
| P1-3 포커스 요소 고유 식별자 | **이미 수집** — 모든 입력·포커스·마커에 IA2UniqueID·unique_id. 단 페이지 로드마다 재할당되는 런타임 ID이므로 세션 간 정렬(E3)은 분석 단계에서 `url+name+role` 키 병용 | 불필요 |
| P1-4 화면 변화 이벤트별 타임스탬프 | **대부분 이미 있음** — 배치별 timestamp 존재. 연속 변화 시 첫 변화 시각이 디바운스에 묻히는 것만 보강 | **소보강 (§3.3)** |
| P1-5 합성기 속도 | **이미 수집** — `environment.speech_rate`(세션 시작 시점) | 불필요 (중간 변경 추적은 P2) |
| P2-6 브라우즈/포커스 모드 이벤트 | 없음 (애드온 미구현) | P2 백로그 |
| P2-7 발화 중단 주체 플래그 | 없음 — `interrupted`만. 중단 시각 직후 input 유무로 유도 가능 | P2 백로그 |
| P2-8 힌트 제공 시각 | **이미 수집** — hint 이벤트에 시각+step | 불필요 |
| P2-9 참여자 배경 설문 | 시스템 밖 — IRB 설문을 참여자 코드로 조인. 필요 시 세션 "평가 환경 기록"란 활용 | 프로세스 노트 |

**요약: P1 5개 중 3개는 이미 수집 중. 신규 구현은 step 결과 코드와 마커
강도 2건 + DOM 첫 변화 시각 소보강 1건.**

## 3. 구현 계획

### 3.1 step 결과 코드 (P1-1) — G_User의 척추

- 스키마: `steps.outcome`(`complete` / `assisted` / `blocked` / 빈값),
  `steps.outcome_note`(포기 사유 등). 기존 DB 자동 마이그레이션.
- 자동 기본값: step 종료 시 해당 step에 힌트가 연결돼 있으면 `assisted`,
  없으면 `complete` — 평가 흐름을 멈추지 않는다.
- UI: step 카드에 종료 후 결과 선택(성공/힌트 후 성공/막힘)과 사유 입력을
  노출해 **회고 때 수정**. 결과는 export JSON·CSV와 결과 패키지에 포함.

### 3.2 불편 강도 (P1-2) — RQ3 연관 분석 정답

- 이벤트 스키마: `marker.payload.intensity`(1~5, 선택적)·`reason`.
- 대시보드 "불편 지점 표시" 버튼: 강도 1~5를 고르는 즉시 입력(기본 3).
- 참여자 단축키(NVDA+Ctrl+Shift+M): 1단계에서는 강도 없이 기록 유지 —
  강도·사유는 **회고에서 마커를 문제로 승격할 때** 심각도·설명으로 보완
  (즉시 자기보고와 회고 평가의 구분은 분석 시 `intensity` 유무로 판별).
- P2: 애드온에서 마커 후 3초 내 숫자 1~5 입력 시 강도 기록.

### 3.3 DOM 첫 변화 시각 (P1-4 보강)

- `dom_mutation.payload.first_change_ts` 추가: 배치 버퍼가 시작된 시각.
  "변화 시작(t)–발화 부재" 결합의 정밀도를 디바운스(450ms+)에서 ms 단위로.

### 3.4 문서 정합

- README 수집표에 이미 수집 중인 항목(요소 고유 식별자, 발화 속도, 힌트
  시각, step 경계 이벤트, DOM 배치 시각)을 명시해 같은 오해 재발 방지.

## 4. P2 백로그 (애드온 수정 필요 — 키트 재배포와 함께)

1. NVDA 브라우즈/포커스 모드 전환 이벤트 (`mode`)
2. 발화 중단 주체 플래그 (`interrupted_by: input | cancel`)
3. 발화 속도 변경 이벤트 (세션 중 rate 조절 추적)
4. 애드온 마커 강도 입력 (마커 후 숫자키)

## 5. 운영 노트 (시스템 변경 불필요)

- **검색 과업은 검색어를 시나리오 문서에 고정 명시** — URL 쿼리를 수집하지
  않으므로 "무엇을 검색했는지"는 시나리오 설계가 담보한다.
- 참여자 배경 설문(SR 숙련도·주 사용 스크린리더·연차)은 IRB 설문으로 받고
  참여자 코드로 로그와 조인한다.
- 세션 간 동일 요소 정렬(E3)은 `url + element.name + element.role` 복합
  키를 기본으로 하고, 페이지 내 재방문 판정은 `ia2_unique_id`를 쓴다.
